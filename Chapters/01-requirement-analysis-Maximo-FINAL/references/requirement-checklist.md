# Requirement Checklist

Apply this checklist across the available evidence.

**Evidence hierarchy**
1. Requirement / Functional Document — primary functional source
2. ADO parent work item — tracking/context
3. Linked ADO child/related tasks — supporting project evidence
4. Other approved documents

**Important:** ADO silence is not a conflict.

Legend: ✅ Present | ⚠️ Ambiguous | ❌ Missing | ⚡ Explicit conflict | N/A

## Source availability
- [ ] Requirement/functional document available
- [ ] ADO parent work item available
- [ ] Relevant linked child/related tasks reviewed
- [ ] Relevant linked documents reviewed
- [ ] Version/status/approval recorded when available

## Business and scope
- [ ] Business objective clear
- [ ] User/persona clear
- [ ] Maximo application/module identified
- [ ] Scope clear
- [ ] Out-of-scope clear
- [ ] Requested change clear

## Functional behavior
- [ ] Trigger/preconditions defined
- [ ] Inputs defined
- [ ] Expected behavior defined
- [ ] Expected result observable
- [ ] Business rules defined
- [ ] Validations defined
- [ ] Positive path defined
- [ ] Negative/error path defined
- [ ] Boundary/empty/null behavior defined
- [ ] Workflow/status transitions defined

## Acceptance criteria
- [ ] Acceptance criteria available where expected
- [ ] Criteria objectively testable
- [ ] Expected outcomes clear
- [ ] No unresolved vague wording
- [ ] No explicit conflict with approved functional evidence

## Data
- [ ] Test data identified
- [ ] Data source/relationships known
- [ ] Setup/preconditions known
- [ ] Expected data changes known
- [ ] Migration/conversion impact addressed where applicable

## Environment/configuration
- [ ] Environment identified
- [ ] Maximo configuration identified
- [ ] System properties/settings identified where applicable
- [ ] External systems/integrations identified
- [ ] Deployment/setup dependencies identified

## Security and cross-cutting
- [ ] Roles/permissions identified
- [ ] Authorization behavior defined
- [ ] Regression impact identified
- [ ] Audit/logging identified where applicable
- [ ] Performance identified where applicable
- [ ] Accessibility/localization identified where applicable

## Evidence relationship
- [ ] Document-only details are not marked as conflicts
- [ ] ADO-only details are assessed for context vs functional significance
- [ ] Child-task details are incorporated when relevant
- [ ] Explicit conflicts cite both sources
- [ ] Missing information is reported only after available evidence is checked
